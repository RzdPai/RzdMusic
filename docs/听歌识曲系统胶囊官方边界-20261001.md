# 听歌识曲接系统胶囊：官方 API 与准入边界

## 结论

本轮通过华为开发者知识库 MCP 检索并读取官方完整文档。**目前未找到面向普通三方应用、合法直接创建听歌识曲系统胶囊的公开接口或已开放准入场景。** 不采用私有权限、typeCode 猜测、把识曲伪装成计时/上传任务、借用播放会话或自绘仿系统胶囊。根据父任务确认，本轮不增加不可用适配器、不增加说明 UI，不修改运行代码，不构建。

这不是“SDK 没有实况窗 API”：Live View Kit 有标准模板及完整创建、更新、结束接口；问题是**识曲业务没有官方列明的可用 event/准入资格**，模板可编译不等于业务获准使用。

## 方案对照

| 能力 | 官方确认 | 对识曲的结论 |
| --- | --- | --- |
| Notification Kit `NotificationContent.systemLiveView` | 不支持三方应用直接创建；仅可在系统代理创建后，由三方发布同 ID 更新指定内容 | 不能自行指定 `typeCode`/通知 ID 创建识曲胶囊 |
| Live View Kit `startLiveView/updateLiveView/stopLiveView` | 公开标准模板；应用前台由用户产生实际服务合约时创建；需要服务权益与系统开关 | 可用于已批准场景，不能据此保证识曲可用 |
| Live View Kit `event: TIMER` | 仅工具类应用专注时刻、番茄时钟、抢票倒计时等；录音、翻译计时、AI 对话时长等明确不适用 | 音乐应用的 12 秒采集不是可冒用的 TIMER |
| Live View Kit `event: PROGRESS` | 用户手动文件上传/下载、音视频编辑资源导入/导出任务 | 识曲采集进度不是该业务，不冒用 |
| Background Tasks Kit `requestSuspendDelay` | 即将退后台时短暂延迟挂起，完成关键操作，完成后取消 | API 不是通知/胶囊创建接口，不保证显示胶囊 |
| `MODE_AUDIO_RECORDING` / `SUBMODE_AUDIO_RECORD_NORMAL_NOTIFICATION` | 真实后台录音的长时任务；子类型官方标为普通文本通知 | 即便申请后台录音也不是“采集→识别→结果”的公开识曲胶囊接口，不为胶囊滥申请 |
| Audio Kit `AudioCapturer` | 实际音频采集，需要 `ohos.permission.MICROPHONE`，使用麦克风音源须真实授权 | 保留现有权限与实际采集；官方检索未确证能由应用配置其隐私提示为识曲胶囊 |
| “MusicRecognition Kit”/系统原生听歌识曲 UI | 使用该名称、听歌识曲、musicRecognition 等多次 MCP 检索未得到对应公开 Kit/API 文档 | 不能凭华为音乐或小艺系统功能推断三方可调用；也不把 SpeechRecognizer 语音转文字当音乐识别 |

## 实况窗具体前置

- 应用需要开通推送服务权益与实况窗服务权益，正式权益按业务场景审核。
- 官方正式申请指南当前要求：**应用已上架、月活数 ≥1000**，提供场景描述、所有状态节点卡片/胶囊/锁屏截图、特殊场景方案和自验结果。方案审核及测试验收总周期约 15 个工作日，不能承诺一定获批。
- 当前公开准入表没有听歌识曲；不能断言满足上架/月活条件就可以申请并获批识曲。需要先向华为确认该业务是否允许接入以及准确 event。
- 支持范围官方为 Phone/Tablet、HarmonyOS 5+、中国境内（不含港澳台）；API 顶部兼容标注不能替代正文范围，不能承诺 PC 显示。
- 本地创建必须应用前台；`isLiveViewEnabled()` 只反映系统开关，不代表场景权益已经开通。未开权益错误码为 `1003500005`。
- 标准模板可以展示固定区 + 强调文本扩展区 + 文本/计时/进度胶囊，无需新增 lock-screen custom extension；但必须先有合法业务资格。

## 录音自动系统胶囊的进一步核查

官方术语表把录音/录屏/通话等列为系统实况通知可能承载的长时任务场景，但这不是应用可指定类型的授权。长时任务完整 API 主类型/子类型对照表明确 `MODE_AUDIO_RECORDING → SUBMODE_NORMAL_NOTIFICATION`；`MODE_AV_PLAYBACK_AND_RECORD → SUBMODE_AUDIO_RECORD_NORMAL_NOTIFICATION`，而 `SUBMODE_LIVE_VIEW_NOTIFICATION` 仅对应 `MODE_DATA_TRANSFER`。不能只依据术语表推导录音申请必定得到可定制系统胶囊。

`startBackgroundRunning(context, bgModes: string[], wantAgent)` 及新 `ContinuousTaskRequest` 重载确实返回 `ContinuousTaskNotification.notificationId`，但**返回通知 ID 不代表返回的是系统实况窗类型**。官方同 ID 实况更新示例是 DATA_TRANSFER 场景，未找到官方录音流程明确允许把普通录音通知改成 `systemLiveView` 或识曲结果胶囊。没有该依据，不实施类型转换、不猜录音 `typeCode`。

[长时任务指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/continuous-task) 已读取全文：真实退后台录制可申请 audioRecording，需要 `KEEP_BACKGROUND_RUNNING` 与 UIAbility `backgroundModes: audioRecording`；系统会做业务一致性检查，业务结束必须及时取消。现需求仅前台短时采集，不能为显示胶囊人为扩成后台录音，采集后网络识别也不能继续冒用录音保活。

## 已读工程调用链与后续风险（本轮不改）

- `features/player/src/main/ets/view/MusicRecognitionPage.ets`：MICROPHONE 用户请求 → 12 秒采集 → `recognizeAll` → 结果/历史；取消及页面离开目前仅 stop recorder。
- `features/player/src/main/ets/recognize/MicRecorder.ets`：48kHz 麦克风采集 →16kHz PCM，stop/release 真实资源。若今后实施系统展示，需同时隔离 create/start 晚到与重复 finish。
- `features/player/src/main/ets/recognize/RecognitionEngine.ets`：酷狗、网易云并行识别。
- `features/player/src/main/ets/recognize/NeteaseRecognizer.ets` 与 AFP WebView：指纹异步返回、网络识别。若允许用户取消后马上重试，应增加带请求 ID 的指纹桥接并隔离迟到回包，不能只靠 UI 状态。
- 已读 `features/player/src/main/ets/util/LyricLiveViewController.ets`：既有歌词控制器使用 TIMER 及自定义锁屏扩展。它不能作为识曲资格依据，不能复用其 event/ID。原代码本轮未改；其是否获权益、其既有 TIMER 业务是否满足当前规范亦未经确认。
- 如未来华为明确允许识曲，生命周期应为：授权成功且真实采集开始后创建；采集节流更新；识别状态更新；成功/失败/无声音/取消/离开全部结束并 `keepTime:0`、胶囊 `status:-1`。每会话独立 ID/世代、异步串行队列；取消期间晚到 start 成功必须结束**旧 ID**，不能清理新会话。标准模板创建必须补齐官方必填 icon/backgroundColor 等，不能盲抄既有代码。
