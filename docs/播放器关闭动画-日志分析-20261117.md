## 二、第 2 次关闭的关键读数列出来

```
close=2 snapshot-request
close=2 snapshot-callback miss code=undefined pix=1     ← 图是好的，标签说 miss（已修，见 §三.①）
close=2 shrink START | snapOwned=1 snapFlight=1 pix=0   ← 此刻 shrink 状态里的 pixmap 还是空
route-remove source=Index index=0                       ← 壳层把路由移除
RzdCloseRender on-disappear rootVis=1 ... closed=0      ← 页面消失时 root 仍 visible=1
close=2 shrink FINISH | snapOwned=1 snapFlight=1 pix=1  ← 补间跑完，pixmap 这时才在
RzdCloseNodes before-hide ... rzd_shrink_overlay_host=[uid:1623 ...]   ← 只有浮层宿主在树上
...
RzdCoverLeak owner-without-pix path=snapshot ...        ← 假报警（已修，见 §三.②）
```

### 从这些数能确定的

1. **快照本身是成功的**（`pix=1`），所以"拍不到图"不是本次的原因。
2. **`shrink START` 时 `pix=0`，`shrink FINISH` 时 `pix=1`** —— 补间启动那一刻，收缩层**还没有图**；
   图是在补间过程中才就位的。真机上这一段就是"封面没有从大飞到小，而是跟着页面一起下去"。
3. `route-remove` 发生在 `shrink START` **之后**，`on-disappear` 时 `rootVis=1`：
   页面已从路由里移除但根节点仍可见 —— 说明**真实页面还在画**，与收缩层重叠。

### 因此两个症状的**主要怀疑点**（尚未逐条证伪）

| 症状 | 怀疑点 | 依据 |
| --- | --- | --- |
| 关闭时封面跟着下滑而不是飞回去 | 收缩层的 pixmap 在 `shrink START` 时为 0 ⇒ 补间期间画的是"空收缩层 + 真页面"，真页面随导航退场下滑 | 上面第 2 条 |
| 展开时没有背景 | 展开路径与关闭共用同一套 `ExpandSnapshot`/`morphOverlay` 状态；关闭那次把 `snapOwned`/`coverHidden` 留在了异常组合（`snapOwned=1` + 假报警说明 own 标记没清干净），下一次展开起手就处在"封面被压、背景层无图"的状态 | `RzdCloseSnap post-cleanup ... snapOwned=1 pix=0 coverHidden=1` |

⚠️ **偶发的合理解释**：这两条都依赖「快照回调与补间启动的先后」。
回调快 ⇒ `pixmap` 在 START 前就位 ⇒ 正常；
回调慢（或壳层 60ms 兜底先触发）⇒ START 时 `pix=0` ⇒ 出现症状。
这与用户说的"不是 100% 出现"吻合。
