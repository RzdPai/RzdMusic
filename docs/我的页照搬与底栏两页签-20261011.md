## 二、代码改动清单

### 1. 「我的」页照搬（`features/setting`）
- `MinePage.ets` 按参考工程 `entry/src/main/ets/views/MineView.ets` 的卡片版式重写：
  账号卡（我们的加法，`HuaweiAccountCard`）→ 快捷入口卡 `QuickCard` → 歌单卡 `PlaylistCard`
  → 记录卡（卡头 = 分段胶囊 + 计数 + `|` + 当前加粗）→ 入口卡 `LinksCard`，外加 `MineTopFade` 顶栏渐隐。
  尺寸/字号照抄参考的 `ui/Theme.ets`（`R_CARD16 / F_SECTION17 / F_ITEM16.5 / F_SUB12.5`、行高 70 / 58、卡头 54…），
  **颜色一律换成我们的 token**（参考那套是洛雪红 + 写死白卡，不能照抄色值）。
- 记录列表仍是 `List` + `LazyForEach` + 稳定 key（卡只是**视觉上**的：卡头 / 行 / 卡底作为相邻 `ListItem` 拼成一张），
  几千条历史不会全建节点。
- 新增二级页 `MinePlaylistPage.ets`（薄壳，渲染的仍是 `features/playlist` 的 `PlaylistsPage`，没有第二份实现），
  已登记进 `features/setting/.../base/profile/router_map.json`。
- 路由：本页自带 `localStack` 管「设置」「全部歌单」；「收藏 → 歌手 / 专辑详情」「歌单 → 歌单详情」
  仍走壳层共享栈 `pageIndexInfos`（要整屏盖住底栏）。

### 2. 壳层：底栏只剩两个页签
- `products/default/src/main/ets/pages/Index.ets`：`HdsTabs` 4 页签 → 2 页签（推荐 / 我的），
  并对 `TabSwitchState.tabIndex` 做越界钳制（旧版留下的 2/3 会落到空白页）。
- `products/pc/src/main/ets/pages/Index.ets`：侧栏同步收成 2 项；
  **并把两个页签合并进同一个 `HdsNavigation(this.pageIndexInfos)`** —— 见下节。

### 3. pc 壳层的路由栈 bug（本轮新发现并修）
官方《Navigation 开发指导》原文：「每个 Navigation 都有自己的路由栈，**不可共享**」。
pc 壳层原来给「我的」那一支塞的是 `HdsNavigation(new NavPathStack())`（inline、没登记路由表），
而 `pageIndexInfos` 只绑在「推荐」那一支上、切页签时**已卸载** ⇒ 在「我的」里点歌单 / 收藏的
歌手·专辑行，push 上去没人渲染（表现：点了没反应）。
改成与 `products/default` 同构：一个 `HdsNavigation(pageIndexInfos)` 包住 `if (tabIndex===0) … else …`。

### 4. 二级页顶部：照片 + 官方光感
- `DetailImmersiveBackdrop.ets` 重写：尺寸改为**显式 `pageHeightVp`**。
  原写法 `height(LayoutPolicy.matchParent)` 挂在「内容驱动」的 Stack 里会量成 0 高 ⇒ 照片整张不画，
  屏上只剩 `HdsNavDestination` 的取色底 —— 正是用户报的「歌手页顶部是纯色，不是歌手照片」。
- `ArtistDetailPage.ets` / `AlbumDetailPage.ets`：标题栏恢复 `blurStrategy: BlurStrategy.ENABLE` +
  `style.systemMaterialEffect = buildTitleMaterial(ambientState.level)`（之前误设成 `MaterialType.NONE`，
  所以光感没了）；`@Monitor('artistPicUrlText' / 'infoPicUrl')` 重新推状态栏取色。

### 5. 流光背景（仍未上机验证）
`PlaybackPage.ets` 的 `FlowLightBackground()` 加能力探测：
`canIUse('SystemCapability.UIDesign.HDSComponent.Core')` 为真才挂 `hdsEffect` 的
`UV_BACKGROUND_FLOW_LIGHT`（并显式 `play()`），否则退回静态 `linearGradient`，两条路都打日志 `RzdFlowLight`。
**说明**：HDS 效果在缺少该 SystemCapability 的设备上不报错、只是**什么都不画**（这也是"看起来没生效"的常见原因）。

## 四、坑（本轮新增，已写进记忆）

1. **注释里出现 `*/` 会当场把注释提前闭合** —— `MinePage.ets` 的文档注释里写了
   `src/main/resources/*/element/color.json`，那个 `*/` 结束掉注释，后面的反引号被当成模板串起点，
   于是整份文件从 236 行开始崩（报 `Unterminated template` + 一串
   `Module declaration names may only use ' or " quoted strings`）。
   症状极具误导性：**报错行号全在"看起来是注释"的地方**。写路径时用 `{base,dark}` 这类写法，别写 `*/`。
2. 排查这类"注释吞掉代码"的语法崩，最快的办法不是等整包构建，而是用 DevEco 自带的 TypeScript 直接解析：
   `tools/ets-syntax-probe.mjs`（把行首 `struct X` 换成 `class X` 后 `createSourceFile` 取 `parseDiagnostics`）
   与 `tools/ets-syntax-suspect.mjs`（只看 TS1443 / TS1127 / TS1434 这几个"被吞掉"的特征码）。
   秒级出结果，比 hvigor 快两个数量级。
3. `assets` 里同一份 `NavPathStack` **不要**塞给两个 `Navigation`（官方：路由栈不可共享）。
4. `HdsNavigation` 的 `navBar` 内容用 `if/else` 二选一是合法的（`products/pc` 现在就靠它做双页签）。

## 五、还没做完 / 有风险的点

- **二级页面的悬浮播放条「真正的官方光感」做不到**（结构问题，不是写法问题）：官方口径为
  「其他组件仅在 Navigation/NavDestination 标题栏或横向 Tabs 中 `barPosition` 为 `BarPosition.End`
  的底部 TabBar 中生效」，即材质层只认**标题栏**与**底栏 TabBar** 两个宿主。
  二级页的播放条既不是标题栏也不是底栏 TabBar，且被包在 `HdsNavigation` 的 content 之内 ⇒
  只能自绘（当前是 `backgroundEffect` 近似）。
  唯一合规做法是把二级页本身放进一个 `HdsTabs({ barPosition: BarPosition.End })` +
  `.barOverlap(true)` + `.vertical(false)`，用 `barFloatingStyle.miniBar` 当播放条，
  并拆掉壳层现有的胶囊（保证全局只有一个形变源）。**这是结构级改动，需要用户拍板。**
- `MinePage` 内层 `Navigation(localStack)` + 系统路由表（跨 Navigation 的 pushPathByName）**没有上机验证**。
