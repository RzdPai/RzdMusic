## 三、这套结构为什么必然出 bug

1. **同一件事有七个来源**：任何一个没准备好，就要靠"兜底层"顶；
   兜底层之间又会互相抢屏（平均色 / 兜底网格 / 真封面）。
2. **本地与在线分叉**：在线走 1~6，本地只走到 C（平均色）⇒ 用户看到的现象就是这个分叉。
3. **跨实例借用 + 手写引用计数**：`bgCacheOwner` 的"孤儿协议"要靠 `onDisAppear` 的时序正确，
   在快速开合时必然出现竞态（历史日志里的 `cache-orphan` / `owner-without-pix` 都是它）。
4. **上游的兜底被照抄，但上游的前置条件没有**（它本地解码必成功、我们异步拿图），
   所以它走不到的分支我们会走到（`0×0 空白` 就是这一类）。

## 四、目标模型（建议）

**一句话：一个来源、一条渲染路径、零"没有封面"分支。**

```
当前歌曲
  └─ CoverProvider（唯一入口，异步）
        ├─ 本地歌曲：内嵌封面 → PixelMap
        └─ 在线歌曲：CoverCacheService(磁盘) → 命中即解码；未命中下载并落盘 → PixelMap
              ↓（失败时返回 undefined，绝不返回"平均色"或占位图）
        MeshCoverBg({ src, srcVersion, seed })
              ↓
        组件内**唯一**兜底：fillFallback（按 seed 四角渐变）
```

要点：

1. **删掉 `bgCachePm` / owner / 孤儿协议 / `sharedMeshAlive` / `MeshWarmState` 借用链**
   —— 有了磁盘缓存（跨启动、按 URL 寻址），进程级借用不再必要。
2. **删掉 `MeshSeedCache`**（4 首字节缓存）—— 与磁盘缓存功能重叠。
3. **本地歌曲也走 `MeshCoverBg`**：把内嵌封面解码成 PixelMap 交给 `src`，
   与在线路径**同一条出口**（这直接修掉"本地只有平均色"）。
4. **删掉 `state.imageColor` 那层背景色**（C 层）与 `effectKit` 平均色路径
   —— 它现在是"本地歌只有一个颜色"的直接原因；占位需求由 A 层（哈希兜底网格）承担。
5. **`imageLabel` 只服务 `<Image>`（封面控件），不再参与背景**。
6. **释放责任单一**：谁 `new`/`decode` 谁 release；跨组件传引用时用"所有权转移"（transfer），
   不搞共享计数。

## 五、分步重建顺序（每步都能单独验收，避免一次性大爆炸）

| 步 | 内容 | 验收 |
| --- | --- | --- |
| **1** | 抽 `CoverProvider`：把"当前歌曲 → PixelMap"收敛成一个异步函数（在线先用现有缓存链，本地先返回内嵌封面） | 本地歌与在线歌**都能**让 `MeshCoverBg` 拿到 `src` |
| **2** | 删 C 层：去掉 `.backgroundColor(state.imageColor)` 与 `effectKit` 平均色（改由 A 层承担） | 本地歌背景不再是纯平均色，而是网格 |
| **3** | 删跨实例借用：`bgCachePm/owner/孤儿/sharedMeshAlive/adoptSharedMesh` 全部移除 | 连续开关 20 次，无 `cache-orphan` 类日志、无残留 |
| **4** | 删 `MeshSeedCache` | 首帧仍有图（走磁盘缓存） |
| **5** | 收尾：`publishMeshSource` 简化为"赋值 + 释放旧值"；`pendingMeshPm` 同理 | 日志里不再有 owner/孤儿协议字样 |

**风险与回滚**：每步一个 commit，`git revert` 即回退；`MeshCoverBg` 的兜底网格（A 层）始终保留，
所以任何一步都不会出现"完全没背景"。
