## 一、用户报的两个 bug：都定位到根因了

### 1. 二级页底部「和一级页一模一样」＋ 系统返回「没反应 / 直接退出 App」

**同一个根因**：`MinePage` 自带一个**内层 `Navigation(this.localStack)`**（`localStackDepth > 0` 时把
「设置 / 全部歌单」画在**本页之内**）。这一层是**页签内容的一部分**：

* 壳层那条 HDS 底栏就画在它上面 ⇒ 二级页底部与一级页**完全一样**（用户原话）；
* 这两次 push **不进 `pageIndexInfos`** ⇒ 壳层 `navDepth` 恒为 0 ⇒
  ① 悬浮播放条不显示；② 系统返回时壳层栈是空的，落到页面级
  `products/default/.../Index.ets: onBackPress()`（播放页没开时返回 false）⇒ **什么都不弹 / 直接退应用**。

**修法**：删掉内层栈（`localStack` / `localStackDepth` / `pushOnLocalStack` / `localStackTopName`
与 `build()` 里那段 `if (localStackDepth > 0) { Navigation(...) }` 全删），所有二级页一律
`this.pageIndexInfos.pushPathByName(<路由名>, param)` 推**壳层共享栈**，`MinePage.build()` 只剩
`HdsNavDestination()` 一支。出口统一过 `pushOnShellStack()`（日志 tag `RzdMineRoute`）。

### 2. 歌手页状态栏「依旧有问题」

**决定性根因：状态栏前景色的判据一直是死代码。**
`statusBarContentColor()` = `isLightBackdrop() ? '#000000' : '#FFFFFF'`，而 `isLightBackdrop()` 对
`avgColor` 算亮度 > 150 才算浅；`avgColor` 唯一来源 `getLargestProportionColor()` →
`common/musicbasic/.../ColorConversion.ets` 的 `dealColor()`，后者把 HSB 亮度**夹到 ≤0.3**（自述注释：
"亮度上限锁死在 0.3…再亮也是接近黑的深色"）⇒ 加权亮度**永远到不了 150** ⇒ 判据恒 false ⇒
**状态栏图标恒白**。而状态栏那一条实际压的是**原始照片**（浅色照片顶部 ⇒ 白图标压浅底）。

另外两条结构性问题：
* **一个属性两个真源**：`aboutToAppear` + 两个 `@Monitor` 共三处
  `WindowUtil.setWindowSystemBarProperties`，同时 build 又挂 `.systemBarStyle(...)`。
  官方《HdsNavigation》原文：「**不建议混合使用 `systemBarStyle` 属性和 window 设置状态栏样式的相关接口，
  例如 `setWindowSystemBarProperties`。**」「初次设置…会备份当前状态栏样式用于后续的恢复场景。」
  「当页面设置不同样式时，**在页面转场开始时生效**」⇒ §11 那条"框架晚一帧、必须手动预下发"的判断是错的。
* **两个参数传同一个值**：官方 `originalStyle` = 初始样式、`scrollEffectStyle` = 动态档**最终**样式，两档背景不同。
* 还有一条：`NavDestination` **默认**就是 `expandSafeArea([SYSTEM],[TOP,BOTTOM])`，而这两页显式只写了
  `[BOTTOM]`，等于把默认的 TOP 绘制扩展**删掉**了 ⇒ 首帧/没图时那一条露出壳层背景（接缝）。

**修法**（`ArtistDetailPage.ets` / `AlbumDetailPage.ets`）：删掉全部 window 级手写下发与
`preapplyStatusBarColor()`，只留 `.systemBarStyle(statusBarOriginalColor(), statusBarScrollEffectColor())`；
判据换成**不经 `dealColor` 的原始色**（新增 `toRgbString()` + 全页唯一 `isLightColor()`）；
照片就位后用"照片里真正压在状态栏那一条"的小区域解码取色（`createPixelMap({desiredRegion, …})` +
`getAverageColor()`，按 `ImageFit.Cover` 逆运算反推区域）；`expandSafeArea` 补回 TOP
（`ignoreLayoutSafeArea` 仍只 BOTTOM —— 它改布局，会把 HDS 返回/分享按钮顶进状态栏）。
标题栏那套沉浸光感（`blurStrategy: ENABLE` / `IMMERSIVE_GRADIENT_LUR` / `buildTitleMaterial`）**一字未动**（用户已确认对）。

## 四、「云端音乐」= WebDAV 曲库（新功能，照搬参考）

* 参考工程：`MineView` 的 `action='cloud'` → `pages/Index.ets` 的 `PAGE_CLOUD` → `views/WebDavView.ets`，
  数据来自 `core/webdav/WebDavLibrary.ets`（PROPFIND 列目录 → 过滤音频 → 曲库）。
  **用户猜的 "LX-Server" 是错的**（以代码为准）。
* 我们落在 `features/sync`：新增 `WebDavTypes.ets` / `WebDavXml.ets` / `WebDavLibrary.ets` /
  `CloudMusicPage.ets`，路由 `CloudMusicPage`。凭据/基址**直接复用**「设置 → 同步 → WebDAV 备份」
  那一套（`WebDavBackupService.readConfig()` → `MusicStoreService.getWebDavConfig()`），**零重填、零硬编码口令**。
* **播放的取舍**（写在文件头，别当"没实现"）：官方**支持**带请求头播放
  （`media.createMediaSourceWithUrl(url, headers)`），但本工程播放器只设 `avPlayer.url`、无处塞
  `Authorization`，而 `features/player` 不在本轮允许改的文件面内 ⇒ 改成**先下载到沙箱 →
  以 `source='local'` 走既有"沙箱文件直路"**。代价：**首播要等整份下完**（第二次起秒播），
  本地多一份缓存（页内有清理出口）。要"边下边播"，只需给播放器加一条
  `mediaSource(url, headers)` 分支（约 10 行，两个调用点）——**要不要做请拍**。
* 没搬的：多选 / 入歌单 / 收藏 / 歌词匹配（参考那套依赖 `SelectSession` 与会话级侧表，本工程没有对应物）。
