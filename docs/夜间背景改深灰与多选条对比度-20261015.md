## B 多选栏对比度

### B.1 先定位"多选栏"到底是哪一个

用户说的"歌单页（如首页每日三十首）多选时 **全选 / 收藏 / 下一首播放 / 删除**"这一条，
唯一命中的是 `features/playlist/src/main/ets/view/PlaylistBatchActionBar.ets`
（`登录 全选/取消全选 · 下一首播放 · 收藏 · 添加到歌单 · 下载 · 删除` 逐字对得上）。
它由 `PlaylistDetailPage.ets:734`（PC 沉浸式分支）与 `:755`（手机/平板分支）两处渲染。

同时这一页在多选时还会把**吸顶的「播放全部」行**切换成
「**已选 N 首 / 全选 / 完成**」—— `PlaylistDetailSongListSection.ets` 的 `PlayAllHeader()`
（`:493-541` 附近），它铺的底是 `StickyPlayAllHeader()` 的 `.backgroundColor(this.backdropColor)`。

### B.2 根因（一句话）

**同一个判据（"这块底是浅还是深"）在两个地方各算了一遍，而两处的阈值不同**：

- `features/playlist/src/main/ets/view/PlaylistDetailPage.ets` 的 `loadBackdropColor()` 原来用
  **WCAG 对比度现算**：
  `this.lightBackdrop = (luminance + 0.05) / 0.05 >= 1.05 / (luminance + 0.05);`
  —— 等价于 **`luminance >= 0.179`**（相对亮度，`linearChannel()` 那一步）。
- `features/setting/src/main/ets/view/ArtistDetailPage.ets:645`（歌手页，用户说"是正常的"）对**同一件事**
  用的是 `(0.299*r + 0.587*g + 0.114*b) > 150`（感知亮度，≈ 相对亮度 0.30）。

而 `ColorConversion.dealColor()`（`common/musicbasic/.../util/ColorConversion.ets:26`）的输出
**并非恒暗**：它把 HSB 亮度落到 0.3 附近，但**色相不同时最大通道仍是 0.3×255 ≈ 76**，
经 sRGB 线性化后**加权相对亮度正好落在 0.18 上下** ⇒ 歌单页那个 `>= 0.179` 的判据
**会在临界点翻成 `true`**，于是 `heroFgPrimary()` 返回 `'#E6000000'`（黑字），
可它压着的那块底（`backdropColor` / 吸顶多选行）只是"中等偏暗" ⇒ **黑底黑字**。
歌手页的 `> 150` 永远到不了 ⇒ 恒定白字，所以它看起来没问题。

**一句话**：不是"没配对"，是**判据的阈值定得太低，在 `dealColor` 自身能产出的取值域里就会翻面**；
而且这个判据在歌单一页里只算一次、被**两层**（正文 + 吸顶多选行）共用，翻面时两层一起黑。

### B.3 修法（三条，缺一不可）

1. **`PlaylistDetailPage.ets`：与其"重算阈值"，不如照抄已验证的对照件**（歌手页）。
   把 `this.lightBackdrop` **定死为 `false`**，并**删掉只服务那个判据的 `linearChannel()`**
   （现在没有调用点）。理由写进了代码注释：本页正文的底就是 `dealColor` 压暗过的色
   （近灰度封面走 `max-min < 1e-3` 分支直接取原灰，否则亮度上限 0.3），恒深底 ⇒ 正文恒白字；
   歌手页这条口径**已上机验证**（用户：「像歌手页就是正常的」）。
   > 这是"真源收敛"而不是"再发明一个阈值"——`statusBar*` 那套（判**原始照片**的）**没动**，
   > 因为它判的是另一层背景，本来就该分开算。
2. **`PlaylistDetailSongListSection.ets`：取色底上的文字色收敛到 `surfaceInk()` / `surfaceInkSecondary()`**
   （恒 `#FFFFFF` / `#B3FFFFFF`），把原来散在 16 处的 `this.fgColor` / `this.fgSecondaryColor`
   全部换成这两个入口。**不再在子组件里按 `backdropColor` 现算第二遍**
   —— 同一个量两处各算一遍，必然在临界底色上打架（一边白字一边黑字）。
3. **`PlaylistBatchActionBar.ets`（底部胶囊操作条）：底与字改成成对的主题 token**
   - 胶囊底：`sys.color.comp_background_tertiary` → **`app.color.capsule_background`**
     （base `#F1F3F5` / dark `#2C2D2F`）
   - 胶囊字：`sys.color.font_primary` → **`app.color.font_primary`**（base `#E5000000` / dark `#E5FFFFFF`）
   - 「已选 N 首歌曲」「取消」：`sys.color.font_secondary` → **`surfaceInk()`**
     （与宿主正文同一条白的结论；这两行是**透明条上的文字**，压的就是页面取色底，
     用主题 `font_secondary` 会被底吃掉）。

### B.4 怎么保证"日间/夜间两种模式都不会再撞色"

- **日间模式**：`lightBackdrop` 恒 false ⇒ 正文/吸顶多选行恒 **白字**，而底是
  `dealColor` 压暗过的深底 ⇒ 白压深，恒定成立。底部胶囊是 `#F1F3F5` 底 + `#E5000000` 字，
  这对值**与页面取色无关**（token 成对），也不会撞。
- **夜间模式**：同一套 `lightBackdrop=false`（它判的是取色底，与系统深浅模式无关），
  胶囊变成 `#2C2D2F` 底 + `#E5FFFFFF` 字 —— **换了一套 token 值，仍然成对**。
- **构造上的保证**：判据只在宿主一处算；子组件与操作条**只消费结论**。
  验证判据行：`git grep -n "lightBackdrop\|surfaceInk\|isLightBackdropColor" -- features/playlist`
  —— 应当只剩宿主 1 处定义、2 处使用 + 两个 `surfaceInk*()` 入口。

### B.5 只改了这条栏（没有做的事）

- **没改多选逻辑**：`PlaylistBatchSelectionStore`、`enterBatchMode` / `exitBatchMode` /
  `toggleSelect` / `isAllSelected` / `batchDelete` / `batchPlayNext` 等**一行未动**。
- **没动播放页形变动画**：`PlaybackPage.ets` / `PlayerExpandState.ets` 只读不写
  （`git status` 里 `PlaybackPage.ets` 是**别的并行切片**在改，不是我）。
- **没有重排布局**：只换了 color 取值与两处 `backdropColor: this.backdropColor` 传参。
