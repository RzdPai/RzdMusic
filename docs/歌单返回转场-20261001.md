## 最终生效：Navigation双侧代理

- 父Navigation属性调用common `navigationReturn`。仅 `POP` 且 `from.navDestinationId` 精确匹配 owning detail 才返回协议；其它页面、非POP均undefined沿系统默认。

## 返回流程

1. 现有入口在 push 前调用 `prepare()`，记录源组件 ID，并创建独立会话。详情 `onReady` 一次性 claim 会话；同封面嵌套页面不能共享上一页的会话。
2. HDS 顶栏/系统返回通过 `onBackPressed`：搜索/多选先退出；首次普通返回交还框架执行 POP，重复请求合并丢弃，绝不在另一页回放。代码不维护延时后退队列，不自行 push/pop。
3. `HdsNavDestination.customTransition` 仅处理 owning session 的 `POP && !isEnter`，可覆盖框架实际提交的 POP（即使没有先触发 onBackPressed）。
4. 重新量源卡、当前 Hero 和 `MORPH_HOST_ID`。源卡未挂、离开宿主可见矩形、Hero已完全滚出视口、宿主不可量、封面已变更时不使用旧起点：改为180ms页面淡出，由框架完成原 POP。源可用时在系统动画事务内用360ms EaseInOut 驱动 clone 从当前Hero返回新的源矩形。
5. entry timer、entry animation、return transaction采用会话+世代校验；旧回调不能结束新会话。页面消失释放自己的会话。

根 Overlay 保持原有 `if(active)`：idle 没有绘制节点，重叠根 Stack `Transparent`、clone `None`，不新增常驻全屏量测节点。量测继续使用 `MORPH_HOST_ID`。

## 官方依据与边界

- [Navigation转场动画](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-navigation-animation)：NavDestination.customTransition适用于单页；event在系统动画事务内更新状态，onTransitionEnd收尾；Navigation.customNavContentTransition优先级更高。
- [HdsNavDestination](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdsnavdestination)：支持customTransition、onReady及onBackPressed；onBackPressed返回false交还框架、true重写返回；不推荐同时设置返回键自定义事件。
- [NavDestination](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-components-navdestination)：API15自定义转场代理参数仅operation/isEnter，协议只有event/duration/curve/delay/end；没有系统边缘手势连续进度/取消回滚代理。

**支持等级：返回提交后的自定义动画，不是系统边缘连续跟手。** 顶栏和系统返回键按官方回调机制处理；系统边缘返回在设备框架提交POP且调用单页delegate时走同一动画。不承诺边缘手势识别中每一帧跟手/取消回滚。要实现可交互转场仍需要`NavigationAnimatedTransition.interactive`与`NavigationTransitionProxy.updateTransition/finishTransition/cancelTransition`协调；本轮父已授权Navigation双侧非interactive代理，只承诺提交后连续飞回，不用应用PanGesture冒充系统边缘手势。框架实际接收方布局和边缘提交/取消行为仍须真机验证。
