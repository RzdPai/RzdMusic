## 二、这轮怎么改的

只动 `products/default/src/main/ets/pages/Index.ets`（**壳层一处**，feature 层零改动）：

1. **`floatingMiniBar()` 换成官方宿主**（照搬参考工程 `lxmusic-harmony` 的 `views/PanePage.ets` 思路）：
   * 单页签 `HdsTabs({ barPosition: BarPosition.End })`，`TabContent()` 故意留空，
     页签栏内容 = `.tabBar(this.floatingMiniBarContent())`；
   * 官方三条件齐：`barOverlap(true)` + `barPosition(BarPosition.End)` + `vertical(false)`；
   * `barFloatingStyle({ barWidth: 三档同值, barSideMargin: 0, barBottomMargin: 0,
     gradientMask: { maskColor: Transparent, maskHeight: 0 }, adaptToHandedness: false,
     systemMaterialEffect: this.ambientTitleMaterial() })` —— **材质档位与标题栏/首页底栏共用同一份**；
   * `barBackgroundColor(Color.Transparent)` + `barBackgroundBlurStyle(BlurStyle.NONE)`：
     `barOverlap` 自带一层隐式厚模糊会盖住材质背板，一律关掉，材质交给 HDS 画；
   * 宿主盒仍是老的几何算盘：宽 = `floatingMiniBarWidthVp()`、高 = `FLOATING_MINI_BAR_HEIGHT_VP`(56)、
     圆角 = 高/2、离底 = `floatingMiniBarBottomMarginVp()`；`clip(false)`（裁了会把 HDS 背板/折射一起裁掉）。
2. **自绘近似彻底删掉**：`backgroundEffect` / `borderWidth` / `borderColor` / 旧注释里那三条"做不到"的理由，
   以及只为它存在的 `floatingMiniBarEffectRadiusVp()` 全部移除。
3. **解掉同 id（这是关键修复）**：首页那条 `miniBar()` 改成
   `if (this.navDepth <= 0) { HomeMiniBarPlayer({ showPreviousTrack: false }) }`
   —— 二级页在栈上时首页底栏**不渲染**，全屏只剩二级页这条官方浮动栏（§17.4-3「两处只能留一处」）。
4. **封面尺寸不动**：`floatingMiniBarContent()` 仍用
   `HomeMiniBarPlayer({ showPreviousTrack: false, followAppMiniBarExpanded: false })`。
   ⚠️ **不要**给它加 `lockTwoRowCoverSize: true` —— 那个参数在当前代码里表示"两排矮封面"，
   会把封面从 **44vp 缩成 30vp**（`HomeMiniBarAlbumCover.coverSideLengthVp()`），
   当年实验用过它、注释也写着"锁定 44vp"，但与今天的实现相反。
5. 日志同 tag 换语义：`RzdSecondaryMiniMaterial` 现在打
   `mode=hds-systemMaterialEffect officialRegion=yes host=single-tab-hdstabs …`（旧的是 `mode=fallback-backgroundEffect … officialRegion=no`）。

## 四、真机必须复验（**不许写成「已修复」**）

1. `grep RzdSecondaryMiniMaterial` → 期望 `mode=hds-systemMaterialEffect officialRegion=yes`；
   同时 `host width=… height=…` 应 ≈ 胶囊宽 × 56。
2. 进二级页看：这条栏是不是**真的**有光感/折射（官方材质），而不是一块半透明板；
   音量键栏、侧边返回手势、上拉起手区是否正常（`TabBar` 会吃它矩形内的触摸）。
3. 从二级页**上拉/点击**打开播放页：形变起点是否还严格贴着这条栏
   （起点走 `getRectangleById(MINI_BAR_ID)`；若起点偏了，先查是不是又出现了两份同 id）。
4. 回首页时首页那条迷你条是否**恢复**（`navDepth` 回 0 才重新渲染）——若卡在空白，
   查 `syncNavDepth()` 有没有被 `onNavBarStateChange` 正常触发。
5. 首页「上下两排」底栏在 push/pop 前后有没有错位（本改动让首页 `miniBar` 在二级页期间为空）。
