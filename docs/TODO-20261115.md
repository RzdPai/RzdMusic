## 二、§7.2 乱码：**交接书给的方法在这批文件上不成立**

### 已做的（76 行，机械还原，一个字都没改意思）

判据不是"看着像乱码"，而是**编码往返**：`line.encode('gbk').decode('utf-8')`
只有「UTF-8 字节被当 GBK 读」产生的乱码才能完整往返成功。

| 文件 | 已还原 |
| --- | --- |
| `common/musicbasic/…/model/PlayerExpandState.ets` | 62 行 |
| `products/default/…/pages/Index.ets` | 9 行 |
| `features/recommendation/…/rawfile/cbg.html` | 5 行 |

### 剩下的**不可还原**（约 5019 行，别白费力气）

| 文件 | 不可还原行数 | 占全文 |
| --- | --- | --- |
| `features/player/…/view/PlaybackPage.ets` | 3102 | 31%（共 10020 行） |
| `common/musicbasic/…/model/PlayerExpandState.ets` | 1369 | 20%（共 6710 行） |
| `products/default/…/pages/Index.ets` | 542 | 15%（共 3708 行） |
| `features/recommendation/…/rawfile/cbg.html` | 5 | — |
| `features/player/…/rawfile/afp/afp_worker.html` | 1 | — |

**为什么还原不了**：这些行是**有损**损坏 —— 乱码里带 `?`（0x3F），说明某个环节把字节替换成了 `?`。
- 整行往返 → 失败；
- 按 `?` 切段逐段往返 → 仍然失败（段内还断在半个字符上）；
- 再来一轮往返 → 得到**另一串乱码**，可读性反而下降（实测 3 行）。

**并且交接书给的"iconv 逐段试还原"也没用**：`_archive/2026-11-14/RzdMusic-src-20261114.tar.gz`
里的同名文件**是同样 3102 / 1369 行乱码**（逐行比对过）⇒ 没有更早的干净副本可抄。

这三块里只有 **1 行是代码**（`PlaybackPage.ets:5863` 的调试字符串
`bad.push('branchSane(panel…neSwiper both true)')`），其余全是注释。

**决定（2026-11-15，用户）：先放着，不处理。**

理由：5019 行全是注释（只有 1 行调试字符串），不影响功能；删了彻底丢信息，
重写等于猜原意。⇒ **标注为已知债，不再尝试**。要动只有一种情况：原作者回来补。
